# 04 AI 辅助使用与责任边界

## 使用方式

本项目由用户与 Codex 对话协作完成。AI 参与需求拆解、Python 实现、LangGraph/工具接入、测试、文档、故障排查和运行记录整理。
AI 生成内容经本地命令、自动化测试、实际 SQLite/HTTP 执行和真实 DeepSeek 调用验证后形成交付材料。
DeepSeek 是项目运行时用于选择工具的模型，与辅助开发的 Codex 是不同职责。

## 当前验证范围

自动化回归 **324 项通过**，其中 HTTP 与人工中断 **75 项**。最新真实 DeepSeek 批次为**六类各两次、12/12 项验收通过**，累计 **62 次模型逻辑调用、58 次模型选择的工具执行**，见 [评估文档](03-evaluation.md) 和 [实际汇总](../examples/04_time_conflict/live-key-paths/summary.json)。
该批包含正常保存、冲突及时段失效、补查成功后重审、人工补资料、授权人工通过及工具错误后模型停止。工具错误的预期结果是明确失败且零草稿；人工驳回/要求修改等其他分支仍主要由离线测试覆盖。
12/12 仅表示本批合成样本的验收结果，不是生产环境成功率或稳定性保证。首批两条真实记录另存为历史证据，不合并进这 12 次统计。
随后又从远程提交 `06fbdf8` 重新克隆并创建 Python 3.12.4 干净环境，安装锁定依赖后 324 项测试、六类离线 HTTP 演示通过，见 [完整记录](../examples/04_time_conflict/clean-environment/summary.md)。此次环境验证由 Codex 执行并归档，没有追加真实模型调用。

## 已确认的用户参与

| 用户动作 | 对最终实现的影响 |
| --- | --- |
| 提供题目与目录要求，要求分阶段推进 | 明确草稿边界和六类必验场景 |
| 指出方案过于复杂，要求按题目精简 | 删除版本历史、复杂时间网格、多 Agent 等非必要范围 |
| 选择 DeepSeek，自行填写本地密钥并启动服务 | 完成真实接口配置与演示运行条件 |
| 要求 HTTP 入口和时间冲突人工中断 | 增加 FastAPI、候选选择、复查恢复 |
| 要求资料缺失和风险人工审核也可中断 | 增加补资料、通过/驳回/要求修改、恢复重审与运行内上下文 |
| 指出工具注册不直观，要求框架方式 | 改为 @tool、bind_tools 和 ToolNode |
| 要求区分 ReAct 与固定分支，并保留两条记录及执行上限 | 增加模型观察/动作证据、公开 reason、incomplete 状态和实际运行验证 |
| 提供 GitHub 交付规范 | 整理五份文档、合成数据、实际输出、Trace 和测试报告 |
| 要求扩充真实关键路径验收、重排首页并准备完整演示 | 增加隔离 Uvicorn 演示运行器、六类各两次真实 DeepSeek 记录、README 架构图与演示指南 |

以上是从协作记录可确认的需求决策、配置和验证参与，不等同于用户独立手写了所有源码。
本次没有可核验的用户手工代码差异或独立源码掌握测试，因此不虚构具体手写代码贡献。后续个人修改应按真实提交补充说明。

## AI 辅助内容及验证

- 模型工具、规则、排期和保存代码：通过可执行测试及七类独立离线回放；实际输出保存在 examples，而非拿 expected.json 冒充结果。
- 模型集成与暂停恢复：通过 HTTP Mock、实际 HTTP/SQLite、中断 ID、重复恢复和占用变化测试。
- 新增资料/风险人工流程：先离线验证，再实际运行 DeepSeek 的资料补充恢复和人工通过两类各两次；合成工具错误和补查成功重审也各运行两次，全部尝试见 examples/04_time_conflict/live-key-paths。驳回/要求修改分支仍由离线测试覆盖。
- 真实决策证据：保留首批两条历史记录和最新 12 次实际输入/输出；通过 tool_call_id 核对模型观察后选择查询、补查、重新审核或结束。强制中断、人工结论及事务复查属于业务执行证据，不称为模型自主决策。
- 文档与记录：以实际运行文件、状态和源代码为依据；首次失败、未实测范围、内存恢复限制均保留说明。

评审可以复现测试并对照 Trace，但测试通过不等同于业务已上线，也不能单独证明个人对所有源码的理解。
本地 .env 不提交；合成资料不含真实业务人员数据；不提交模型内部思维过程，只保存公开动作依据。
