## 已完成：草稿保存

- 按 request_id 唯一保存当前草稿，相同请求复用 draft_id，不创建第二份。
- 重新提交仍检查最新占用，可更新当前建议；不维护版本历史。
- 同一 request_id 对应不同输入返回冲突；修改输入使用新 ID。
- 保存前检查时段，以数据库实际提交结果决定成功或失败。
- 保存服务校验原始要求，拒绝未经用户确认就接受新的硬性时间。

验收：成功保存、重复只有一份、占用变化后调整建议、保存失败如实返回。

## 单 Agent 与交付

- 一个 LangGraph Agent 调用素材读取/补查、规则检查、时段查询、草稿保存工具。
- 模型根据工具结果选择补查、替代时段、请求确认或阻断。
- 业务服务执行规则、时间计算和真实保存，模型不能编造保存结果。
- 硬性时间变更只输出待确认建议；用户明确给出新要求后按新请求处理。
- 交付命令行及按最新需求增加的 HTTP 入口、运行说明和工具调用记录。

验收六类：正常排期、信息缺失、规则风险、时段冲突、重复提交、保存失败。
无可用时段作为补充边界保留。通过验收即交付，只保存草稿，不执行发布。
